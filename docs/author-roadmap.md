# 灵写 · 作者视角功能路线图（v0.4–v0.6）

> 状态：规划稿（2026-10-17）。对应功能尚未实现，本文只描述要做什么、为什么做、按什么顺序做。
> 依据：`author-research.md` 的作者调研、`PROGRESS.md` 的已实现能力、`docs/v0.2-plan.md` 的产品约束，以及 2026-10 对 HEAD `558debe` 的代码核对与审核结论。
> 详细任务卡：v0.4 见 [v0.4-plan.md](v0.4-plan.md)，v0.5 见 [v0.5-plan.md](v0.5-plan.md)，v0.6 见 [v0.6-plan.md](v0.6-plan.md)。

## 0. 这份路线图只回答三个问题

1. **作者每天都会做的动作，能不能更省事？**（码字、查设定、发布、备份）
2. **不可逆的损失，能不能更少？**（丢稿、升级失败、改错正文、平台审核）
3. **能不能少离开正文？**（查设定、查前情、查伏笔、问 AI）

一个功能如果三条都不占，就不进路线图。灵写已经不缺功能数量：编辑、设定库、三级大纲、伏笔台账、一致性检查、AI 工具条、统计、导出、备份、应用内更新都已存在。缺的是「每天敢用、长期能用」——长篇不卡、旧稿能迁进来、发布前心里有数、写作时不被打断。

## 3. 版本路线

### v0.4「能长期写」（数据库仍为 8，不做迁移）

**目标：** 一本 100 万字、500 章的作品，从导入、日常写作、搜索、备份到删除，都不因为数据量而失效。

- 长篇性能与数据安全（前置）
- 作品导入
- 平台格式导出 + 发布前检查
- 专注写作模式
- 编辑器速查

**为什么先做：** 导入会立刻把作品规模放大一个量级；如果先做花哨功能，导入后的第一周就会撞上全量加载、备份 OOM 和索引重建。v0.4 不改数据库，降低发布风险。听稿（TTS）放到 v0.5，因为系统语音引擎的机型差异需要单独验证，v0.4 先把数据安全和迁移做稳。

**版本门：** CI 全绿；100 万字夹具真机走通；备份/导入 round-trip；无新增数据库迁移；四语截图；`versionCode=16`。

### v0.5「写作闭环」（数据库 8→9）

**目标：** 作者能根据追读数据回头改章，能把偏离的章纲回写，能在同一个地方查到人物/物品/地点/信息差，能解释自己用了多少 AI。

- 追读数据复盘（`read_metrics`）
- 大纲-正文同步（`chapter_plan_versions`、`chapter_plans.storyTime`）
- 一致性扩展 + 章节事件轴
- AI 使用体检
- 听稿（系统 TTS）

**版本门：** 迁移 8→9 全链通过；旧备份可导入；章号重排后追读数据不错位；`versionCode=17`。

### v0.6「差异化」（数据库 9→10）

**目标：** 把 AI 从「一排按钮」变成写作节奏的一部分；让系列作者把世界观沉淀下来。

- 场景级 AI 协作流
- 伏笔回收日历
- 系列共享设定（`series`、`books.seriesId`、`series_lore`）

**版本门：** 迁移 9→10；备份含系列；`versionCode=18`。

### v0.7+ 备选（不承诺）

- EPUB 导入、DOCX/EPUB 导出
- 加密 WebDAV / 局域网同步（不建账号、不引入服务器）
- 写作打卡、头脑风暴画布、和角色对话
- 读者端/社区不做；云账号强绑定不做

## 4. 技术前置（不修会拖垮新功能）

这些不是「新功能」，但必须在 v0.4 先做，否则导入/追读/备份都会放大问题：

1. **全量加载正文**：`BookRepository.hero()`、`SerialBoard.state()`、`Notifier.foreshadowDigest()`、`ContextEngine.build()/refresh()/brief()`、`Consistency.basis()` 多处用 `chaptersOnce`（`SELECT *`）。改为窄查询/聚合查询。
2. **索引重建**：`BookRepository.renumber()` 清空整书 `chapter_index`；`ContextEngine.refresh()` 每次 AI 调用全量扫章节。改为只处理过期/受影响章节。
3. **搜索**：`ContextEngine.search()` 把 `Int.MAX_VALUE` 传给 SQL，再在内存取交集。改为 SQL `LIMIT` + 分批。
4. **备份**：全内存构建 JSON，`chapter_versions` 每章最多 50 个自动版本。默认精简自动版本，保留手动/回滚/AI 版本；完整备份作为选项。
5. **升级**：没有迁移前自动备份。启动时在 Room 打开前做原始库快照，保留最近 2 份，可导出，不自动恢复。
6. **删书**：不清理 FTS 与地图/封面文件。删书路径集中清理。
7. **同版本 schema 风险**：v0.3.0 的 schema 8 identityHash 尚未用 v0.2.12 真实库验证。v0.4 不改表，但发布前必须完成 v0.2.12→v0.3.0 / v0.3.0→v0.4.0 真机覆盖升级冒烟；后续每次迁移都走「迁移前快照 + 迁移测试 + 真机升级」。

## 5. 指标与验证

灵写不做遥测，所以不用「上传埋点」证明成功。每个版本用下面三类证据：

**A. 工程门（必须全过）**

- CI：`assembleDebug assembleRelease lintDebug testDebugUnitTest` 全绿。
- 迁移：逐版本迁移测试 + 全链打开测试；v0.4 无迁移。
- 测试：备份/导入 round-trip、100 万字夹具、章号重排、AI 标记占比、提示词契约。
- 隐私：新功能断网可用（AI 可选分析除外，且必须显式触发）；无新增权限/网络请求。

**B. 真机门**

- 100 万字 / 500 章夹具：导入 → 书写 → 搜索 → 备份 → 覆盖导入 → 删除，无 ANR/OOM。
- 覆盖升级：上一版正式 APK 写入数据 → 安装新版 → 检查作品/章节/设定/伏笔/追读数据完整。
- 专注模式连续 30 分钟、听稿连续 10 分钟、事件轴 500 章滚动，无崩溃。

**C. 作者门（每个版本 3–5 位真实连载作者）**

| 版本 | 任务 | 通过标准 |
|---|---|---|
| v0.4 | 导入自己的旧稿并找到错章；复制一章到平台后台；专注写 30 分钟；速查任意设定 | ≥ 4/5 完成，且愿意在日常使用 |
| v0.5 | 录入一周追读数据并指出最大掉点；回写一章章纲并撤销；看懂 AI 使用报告口径 | ≥ 4/5 完成 |
| v0.6 | 两本书共用系列圣经；伏笔日历回答「下一章该收哪条」 | ≥ 4/5 完成 |

指标只用于内部判断，不对外承诺留存/增长数字；访谈记录和可选的本地导出（追读报告、AI 使用报告）由作者自愿提供。

## 6. 明确不做

- 不做全自动生成整本、自动发布、批量养号；不做 AI 检测规避、「降 AI 率」「过检测」「伪装人写」。
- 不做云账号强绑定、广告/统计 SDK、遥测；多端只考虑加密导出/导入，后续再评估加密 WebDAV（不建账号）。
- 不抓取平台后台、不做平台数据爬虫、不做付费内容 OCR/搬运。
- 不内置第三方敏感词库；风险词表由作者自行导入，检查结果不构成平台合规保证。
- 不仿写在世作者文风；「去 AI 腔」只改善文风，不承诺规避检测。
- 不做实时多人协作、社区/读者端、书城；不做自动改正文（作者逐条确认是唯一路径）。

## 7. 风险与假设

| 风险 | 影响 | 应对 |
|---|---|---|
| 100 万字真机性能未实测 | 窄查询仍可能不够 | 先做夹具和真机门；不达标不发布 |
| 导入标题误判 | 章节错乱 | 预览 + 三种拆分方式 + 可取消 + 失败回滚 |
| 备份精简丢自动历史 | 少恢复点 | 手动/回滚/AI 版本全保留；完整备份可选；文案写明 |
| 升级快照只备份不恢复 | 灾难时需人工 | 可导出；文档写清；后续再评估 |
| 追读数据格式变化 | 解析失败 | 表头别名 + 手动录入 + 逐行错误 |
| 一致性新类型误报 | 噪音 | 类型开关 + 故意为之抑制 + 逐字引文 |
| 系列语义误解 | 以为全书自动生效 | 明确参考库，复制到本书才生效 |
| 平台规则变化 | 检查被当合规保证 | 明示不构成保证；词表作者维护 |
| 范围蔓延 | v0.4 不发布 | 每个版本先过版本门；新想法进 v0.7 |

**假设：** 目标仍是 Android 12+；不做 iOS/Web；平台数据由作者手动提供；系统 TTS 可用（不可用则降级）；v0.4 不改数据库是硬约束；主维护者本机无 JDK，以 CI 为准。

## 9. 待验证（发布前补）

1. 3–5 位作者的可用性访谈：手机码字比例、辅助模式接受度、导入来源、追读数据来源与格式、系列需求、听稿习惯。
2. 100 万字 / 500 章真机压测：书架、作品页、编辑器、搜索、备份、导入、删除。
3. v0.2.12 → v0.3.0 → v0.4.0 覆盖升级冒烟（`PROGRESS.md` 已记录 v0.2.12→v0.3.0 待做，不得跳过）。
4. 新提示词的真实模型评测：章纲回写、追读诊断、一致性新增四类；沿用 `docs/ai-prompt-eval.md` 的方法。
5. 平台导出格式与风险词表：由作者用真实后台预览校准，App 不宣称官方格式。
