# 灵写 v0.6 计划：差异化

> 状态：规划稿（2026-10-17），尚未实现。
> 上级文档：[author-roadmap.md](author-roadmap.md)。前置版本：[v0.5-plan.md](v0.5-plan.md)。
> 本版本**数据库 9 → 10**（系列共享设定），必须显式迁移、提交 schema、补迁移测试和真机覆盖升级。

## 1. 范围

1. 场景级 AI 协作流：写前 / 写中 / 写后，把现有工具串成写作节奏。
2. 伏笔回收日历：按计划回收章分组、按更新速度估算、每三章埋新伏笔提醒。
3. 系列共享设定：`series` + `books.seriesId` + `series_lore`，跨书参考库，复制到本书才生效。
4. 发布 v0.6.0（versionCode 18，versionName 0.6.0）。

**不在本版本：** 读者端/社区、云账号、WebDAV 同步、EPUB 导入、AI 自动写整本。

## 2. 数据库 9 → 10

### 2.1 新表

```sql
CREATE TABLE IF NOT EXISTS `series` (
  `id` INTEGER PRIMARY KEY AUTOINCREMENT NOT NULL,
  `name` TEXT NOT NULL,
  `note` TEXT NOT NULL DEFAULT '',
  `createdAt` INTEGER NOT NULL
);

CREATE TABLE IF NOT EXISTS `series_lore` (
  `id` INTEGER PRIMARY KEY AUTOINCREMENT NOT NULL,
  `seriesId` INTEGER NOT NULL,
  `type` TEXT NOT NULL,
  `name` TEXT NOT NULL,
  `aliases` TEXT NOT NULL DEFAULT '',
  `role` TEXT NOT NULL DEFAULT '',
  `fields` TEXT NOT NULL DEFAULT '[]',
  `states` TEXT NOT NULL DEFAULT '[]',
  `relations` TEXT NOT NULL DEFAULT '[]',
  `updatedAt` INTEGER NOT NULL,
  FOREIGN KEY(`seriesId`) REFERENCES `series`(`id`) ON UPDATE NO ACTION ON DELETE CASCADE
);
CREATE INDEX IF NOT EXISTS `index_series_lore_seriesId` ON `series_lore` (`seriesId`);
```

### 2.2 修改表

```sql
ALTER TABLE `books` ADD COLUMN `seriesId` INTEGER
  REFERENCES `series`(`id`) ON UPDATE NO ACTION ON DELETE SET NULL;
CREATE INDEX IF NOT EXISTS `index_books_seriesId` ON `books` (`seriesId`);
```

`books.seriesId` 可空：删系列不删书，只把书移出系列。若 Room 对 `ALTER TABLE ... REFERENCES` 的 schema 校验不通过，备选方案是重建 `books` 表并复制数据（保持列顺序、默认值、索引与外键），迁移测试必须覆盖。

### 2.3 迁移与备份

- `LingDatabase.version = 10`；新增 `MIGRATION_9_10`；提交 `schemas/.../10.json`。
- `Backup.tables` 顺序调整为：`series`、`books`（`seriesId` → `series`）、`volumes`、…、`series_lore`（`seriesId` → `series`）、`read_metrics`。`books` 的外键映射增加 `seriesId`；`series_lore` 只依赖 `series`。
- 覆盖导入反向清理顺序包含新表；合并导入重映射 `books.seriesId` 与 `series_lore.seriesId`。
- 旧备份没有 `series` 表时正常跳过；新备份在 schema 字段写 10。
- 迁移测试：`migrate9To10()` 建 v9 库 + 书/章节/设定/追读 → 迁移 → 断言新表、`seriesId`、索引、数据；全链打开；备份 round-trip（含 `seriesId` 重映射）。

## 3. 任务卡

### S1 场景级 AI 协作流

**目标：** 打开一章，按「写前 → 写中 → 写后」三步得到恰到好处的帮助，而不是在一排工具按钮里找。

**用户故事：** 我知道要写什么，但不知道从哪下手；写完又怕漏了钩子和伏笔。

**流程：**
- 写前：本章目标/情绪、开场三选一（复用现有给方向/起草能力）、本章必须推进的线索/伏笔提醒。
- 写中：卡文急救、随手问（复用现有入口）。
- 写后：本章自查清单（章纲落实、伏笔、章末钩子、一致性、校对入口），一键跳到对应工具。
- 新 `data/WriteFlow.kt` 状态机 + `ui/routes/WriteFlow.kt` 面板。
- 辅助模式：只产出候选/便签，不写正文；生成模式沿用现有草稿区。所有 AI 输出需作者确认。

**文件：** `data/WriteFlow.kt`（新增）、`ui/routes/WriteFlow.kt`（新增）、`ui/routes/EditorRoute.kt` / `EditorScreen.kt`（入口）、i18n。

**边界与失败：** 无章纲/无设定/无前情；AI 失败降级为本地清单；生成中切页/切后台；辅助模式零正文写入（测试兜底）；面板与键盘/IME 冲突。

**测试与验收：** 状态机单测；辅助模式零正文写入（扩展 `ModeAcceptTest`）；失败降级；浅/深色截图。验收：三步都能走通；任何一步都可以跳过；不产生自动写入。

**估时：** 3 天。 **依赖：** v0.5 完成（复用大纲落实/一致性/校对）。

### C1 伏笔回收日历

**目标：** 作者按未来章节看「哪几章该回收哪条伏笔」，并按当前更新速度估算还需几天。

**用户故事：** 伏笔台账只告诉我「逾期」，但我需要知道下一章该收哪条、按日更还要几天。

**实现：**
- 新 `data/ForeshadowCalendar.kt`（纯函数）：
  - `groupByPayoff(foreshadows)` → 按计划回收章分组；逾期/临期/未定。
  - `etaDays(rows, recentChapterPace)`：按最近 7 天日均章数估算；无速度数据时显示「—」。
  - `pacingCheck(foreshadows, currentChapter)`：每 3 章是否至少埋一条新伏笔（调研建议；只提示，不判错）。
- 入口：伏笔 tab 顶部卡片 + 连载看板；点击跳到对应伏笔/章节。
- 只读，不改数据；不调用 AI。更新速度优先用最近 7 天 `state='done'` 且 `updatedAt` 在窗口内的章节数；不足 3 天数据时显示「—」。

**文件：** `data/ForeshadowCalendar.kt`（新增）、`ui/routes/CheckRoute.kt`、`ui/routes/SerialBoardCard.kt`、i18n。

**边界与失败：** 无 `payoff` 的伏笔归「未定」；计划章号小于当前章（逾期）；速度数据不足；同一章多条；伏笔被删；章号重排后 `payoff` 已由现有逻辑重映射。

**测试与验收：** `ForeshadowCalendarTest`（分组、逾期、ETA、每三章规则）；UI 截图。验收：日历能回答「下一章该收哪条」；不修改任何伏笔。

**估时：** 2 天。 **依赖：** 无（可与 S1 并行）。

### L1 系列共享设定

**目标：** 同一世界观写多本书的作者，把力量体系、地理、组织、核心人物放进系列圣经，写新书时直接引用。

**用户故事：** 我的第二本书和第一本同一个世界，不想把设定复制一遍，也不想两本书的设定越改越乱。

**数据：** `series`、`books.seriesId`、`series_lore`（见 §2）。`series_lore` 用 JSON 存字段/按书状态/关系：`fields` 为 `[{"k":"境界","v":"筑基"}]`，`states` 为 `[{"fromChapter":1,"field":"境界","value":"筑基"}]`，`relations` 为 `[{"to":"沈砚","label":"师徒"}]`（按名字引用，不用跨书 id）。第一版不自动参与书内一致性检查，只作为参考库；「复制到本书」才写入 `lore_cards`/`lore_states`。

**UI：**
- 书架/设置入口「系列」→ 系列列表 → 系列详情（书籍列表、共享卡编辑、复制到本书）。
- 书籍可移入/移出系列（`seriesId` 置空不删书）。
- 复制规则：`LoreCardEntity.bookId` 指向目标书，`type/name/aliases/role` 照搬，`fields` 追加一项「系列来源 = 系列名」，不设置 `firstChapter`，`inject="auto"`；重名时提示「已存在同名卡」，不自动覆盖。
- 系列卡只读展示 + 编辑；不把系列卡直接注入 AI 上下文，避免跨书剧透/混淆。

**文件：** `data/db/SeriesEntities.kt`（新增）、`Daos.kt`、`LingDatabase.kt`、`data/db/Entities.kt`（`seriesId`）、`data/Series.kt`（新增）、`ui/routes/SeriesRoute.kt`（新增）、`ui/LingWriteApp.kt`、`data/Backup.kt`、i18n。

**边界与失败：** 删系列不删书；删书不影响系列卡；复制重名；合并导入重映射；旧备份没有 series；系列卡 JSON 损坏（跳过并提示）；书籍移出系列后书内设定不受影响；系列卡不参与一致性检查（文案写清）。

**测试与验收：** 迁移 9→10、备份 round-trip、系列 CRUD、复制到书、跨书隔离、删除语义；截图。验收：同一系列两本书可共享卡；复制后书内一致性可用；删除系列书仍完整。

**估时：** 5 天。 **依赖：** 数据库 9→10。

## 4. 执行规则

- **数据库：** 先合 `v0.6/schema10`（schema、迁移、备份、测试），再合 S1/C1/L1；功能 PR 不再改 schema。
- **PR：** `v0.6/schema10`、`v0.6/write-flow`、`v0.6/payoff-calendar`、`v0.6/series`、`release/v0.6.0`。
- **测试：** 迁移、备份、状态机、日历纯函数、系列 CRUD/复制/删除；UI 截图；真机升级。
- **i18n：** 四语；AI 提示词中文；系列/共享文案避免「自动生效」误导。
- **隐私：** 系列数据只在本机；不做跨设备同步；不上传系列设定。

## 5. 产品约束

1. 不做自动写正文/自动发布；场景流只给候选/清单。
2. 系列卡不自动进入 AI 上下文，避免跨书剧透；复制到本书后才参与。
3. 不做云同步/账号；系列数据随整库备份/导入移动。
4. 不帮助规避 AI 检测；不做读者端/社区。

## 6. 风险

| 风险 | 影响 | 应对 |
|---|---|---|
| 迁移 9→10 外键/索引出错 | 无法启动 | 显式迁移 + 全链测试 + 升级前快照 + 真机升级 |
| 系列语义被误解 | 以为自动生效 | 文案「参考库，复制到本书才生效」；UI 区分 |
| 复制重名/覆盖 | 书内设定被改 | 重名提示；不自动覆盖；复制后可在设定库手动删除 |
| 场景流变成「自动写」 | 违反红线 | 辅助模式零正文写入测试；所有输出候选 |
| 伏笔日历估算误导 | 作者按错误节奏安排 | 显示「按最近 7 天速度估算」；数据不足显示「—」 |
