# 灵写 v0.4 计划：能长期写

> 状态：规划稿（2026-10-17），尚未实现。
> 上级文档：[author-roadmap.md](author-roadmap.md)。产品约束沿用 [v0.2-plan.md](v0.2-plan.md) §5。
> 本版本**不改数据库**（Room 仍为 8），不新增迁移；所有数据库变更从 v0.5 开始。

## 1. 范围

1. 修长篇性能与数据安全（P0，前置）。
2. 作品导入：TXT / Markdown / DOCX → 分卷、分章。
3. 平台格式导出（模板可选）与章节复制；发布前本地检查。
4. 专注写作模式（含打字机滚动、目标、计时）。
5. 编辑器速查（设定 / 伏笔 / 前情 / 搜索）。
6. 发布 v0.4.0（versionCode 16，versionName 0.4.0）。

**不在本版本：** 追读数据、大纲回写、一致性扩展、系列、TTS、EPUB 导入；不做任何数据库迁移。

## 3. 任务卡

### P0 长篇性能与数据安全

**目标：** 500 章 / 100 万字规模下，书架、作品页、看板、上下文、搜索、备份、删除都按「只读需要的数据」工作；升级前留下原始库快照。

**用户故事：** 我的书很长，打开 App 不该因为「它在加载所有正文」而卡；备份不该在最需要的时候 OOM；升级失败时至少还有一份原始库。

**数据与接口（不新增表）：**
- `ChapterDao` 新增：
  - `headersOnce(bookId)`：`SELECT id, bookId, volumeId, number, title, '' AS content, wordCount, state, aiMarks, updatedAt, deletedAt ...`
  - `lastContent(bookId)`：最近更新章正文，仅 1 章。
  - `maxNumberWithWords(bookId)`：过滤 `deletedAt = 0` 且 `wordCount > 0`。
  - `previous(bookId, number, n)` 已有，继续用于前情结尾。
  - `staleIds(bookId, except)`：`chapters LEFT JOIN chapter_index ON chapterId`，`at IS NULL OR at < updatedAt`，过滤 `deletedAt = 0`。
  - `lastNContent(bookId, n)`：给 `OutputLang` 用。
- `BookDao` 新增 `totals(bookId)`：字数合计 + 章数，均过滤 `deletedAt = 0`。
- `BookRepository.hero()` 改用 `headersOnce` + `totals` + `lastContent`；不再加载全书。
- `SerialBoard.state()`、`plan()` 改用 `headersOnce`；`Notifier.foreshadowDigest()` 改用 `maxNumberWithWords`。
- `ContextEngine.refresh()` 用 `staleIds` 逐章取正文重建；`build()` 的分层摘要用 `headersOnce` + `summaries`；`brief()` 的 `PrevSummaries` 用 `headersOnce`；`titleIdeas()`/`afterChapterDone()` 用 `headersOnce`。
- `Consistency.basis()` 的「前 15 章」改用 `chapters.previous`（已有正文）或摘要，不再 `chaptersOnce` 全量。
- `ContextEngine.search()` 每个词 SQL `LIMIT 200`，交集后再 `take(limit)`；语义检索同样限量。
- `BookRepository.renumber()` 记录章号变化的 id，只删这些 id 的 `chapter_index`；不再整书清空。
- `BookRepository.deleteBook()`：删书前用 `SELECT id FROM passages WHERE bookId=?` 取 rowid，分批 `DELETE FROM passages_fts WHERE rowid IN (...)`；再删 `filesDir/maps`、`filesDir/covers/{bookId}.png`；删除逻辑集中到 `deleteBookFiles(bookId)`。
- `Backup.dump()` 的 `schema` 改为 `db.version`（不再写死 8）。
- `Backup.writeZip(out, ctx, prefs, includeAllVersions = false)`：默认对 `chapter_versions` 只保留每章最近 3 个 `kind='auto'`，`manual/rollback/ai` 全保留；`dump` 增加 `includeAllVersions` 参数；导出页增加开关和体积提示。
- 新增 `data/UpgradeGuard.kt`：核心是纯函数 `snapshot(dbFile, walFile, shmFile, currentVersion, outDir): File?`（可单测）；`AppGraph.init` 在 `LingDatabase.build` 之前调用，用只读 `SQLiteDatabase.openDatabase` 读 `PRAGMA user_version`，若 `0 < old < 当前版本`，把 `lingwrite.db`、`-wal`、`-shm` 流式写入 `filesDir/backups/upgrade-vX-to-vY.zip`，保留最近 2 份；同 from→to 已存在则不重复；新装（版本 0）跳过。
- `DataRoute` 备份页列出升级快照，可导出/删除；不提供自动恢复（文档写明）。

**文件：** `data/db/Daos.kt`、`data/BookRepository.kt`、`data/SerialBoard.kt`、`data/Notifier.kt`、`data/ContextEngine.kt`、`data/Consistency.kt`、`data/ai/OutputLang.kt`、`data/Backup.kt`、`data/UpgradeGuard.kt`（新增）、`AppGraph.kt`、`ui/routes/DataRoute.kt`、`ui/routes/CheckRoute.kt`、`ui/routes/IdeasRoute.kt`、`ui/routes/WorkRoute.kt`。

**边界与失败：**
- 0 章 / 空书；回收站章节不参与统计；WAL 存在时快照仍包含 `-wal`/`-shm`。
- 磁盘不足：快照失败不影响启动，只记录错误并在备份页提示；不得阻塞 Room 打开。
- 精简备份：作者仍可回滚手动/回滚/AI 版本；完整备份超过读取上限时明确报错。
- 删书时 FTS 删除失败：重试或下次启动清理，不阻断删书。
- 索引失效：`renumber()` 后只清受影响章；`refresh()` 仍能发现未索引的新章。

**测试与验收：**
- 新增 `LongBookQueryTest`：内存 Room 建 500 章，每章 2000 字；用 Room 的 query callback 记录 SQL，断言 `hero`/`SerialBoard`/`refresh` 路径没有 `SELECT * FROM chapters` 全表正文查询（只有 `content=''` 投影或单章取正文）；同时断言章号/字数正确。
- `SearchLimitTest`：构造大量命中，断言每词 SQL 有上限、最终结果 ≤ limit。
- `DeleteBookCleanupTest`：建书、写章、建 FTS、写封面文件；删书后 `passages_fts` 无残留、文件删除、其他书不受影响。
- `BackupSlimTest`：默认备份保留手动/回滚/AI 版本 + 最近 3 个 auto；完整备份保留全部；两种 round-trip 内容一致；旧 schema 8 备份可导入。
- `UpgradeGuardTest`：用 `SQLiteDatabase` 建 `user_version=7` 的临时库，调用纯函数 `snapshot(...)`，断言 zip 含 db/wal/shm；版本为 0 或等于当前时返回 null。
- 验收：真机 100 万字夹具上，书架/作品页/看板打开无 ANR；备份导出无 OOM；删书后 DB 体积明显下降。

**估时：** 4 天。 **依赖：** 无。

### I1 作品导入

**目标：** 作者把自己的旧稿（TXT/Markdown/DOCX）导入为「作品 + 分卷 + 章节」，预览可改，失败不落库。

**用户故事：** 我手机上已经有一本 80 万字的稿子，不想一章一章复制。

**入口与流程：** 书架「新建」sheet →「导入作品」→ SAF 选择文件 → 解析（进度）→ 预览（书名、卷数、章数、前 20 章标题、警告）→ 选拆分方式（按章标题 / 按长度 / 不分章）→ 确认书名 → 写入 → 打开作品页。取消不写库。

**数据与接口：**
- 新增 `data/Import.kt`：
  - `ImportOptions(mode: SplitMode, fallbackLength: Int = 3000, encoding: Charset? = null)`
  - `ImportPreview(bookTitle, volumes: List<ImportVolume>, warnings: List<String>)`
  - `suspend fun parse(ctx, uri, options): ImportPreview`
  - `suspend fun commit(preview, bookTitle): Long`
- 不新增表；`ChapterDao` 增加 `insertAll(chapters)`。
- 事务内写 `books` / `volumes` / `chapters`；不复用 `createBook`（避免多出空白章）；写入后 `books.touch`。
- 进度回调 `(stage: String, done: Int, total: Int)`。

**解析规则：**
- TXT：UTF-8（含 BOM）/ UTF-16（BOM）/ GB18030 自动检测；失败时返回可选编码让作者重试。
- Markdown：`#`/`##` 标题优先；否则复用章节正则；标题行去掉 Markdown 标记。
- DOCX：`ZipInputStream` 读 `word/document.xml`，`XmlPullParser` 提取 `w:p` 段落、`w:t` 文本、`w:br` 换行、`w:tab` 制表；忽略图片/脚注/批注；单 entry ≤ 20MB。
- 章节标题：`^第[0-9零〇一二三四五六七八九十百千万两]+[章节回卷集部篇]...`、`^Chapter\s+\d+` 等；仅整行、长度 ≤ 60、非空；卷标题单独识别。
- 无 ≥2 章标题时默认「按长度」3000 字/章；预览可切换。
- 标题只存名称，复用 `Naming.stripChapter/stripVolume`；章号按顺序生成；字数用 `Words.count`。
- 限制：文件 ≤ 20MB、章节 ≤ 5000、单章标题 ≤ 80 字。

**文件：** `data/Import.kt`（新增）、`ui/routes/ImportRoute.kt`（新增）、`ui/LingWriteApp.kt`（路由）、`ui/routes/ShelfRoute.kt`（入口）、`ui/screens/ShelfScreen.kt`（按钮）、`data/db/Daos.kt`、i18n。

**边界与失败：** 空文件/全空白；编码乱码；无标题；标题误判（预览可改「不分章」）；超大文件；解析取消；写入失败回滚；同名作品允许并自动加序号；导入后书架排序与封面占位。

**测试与验收：**
- `ImportTest`：UTF-8 / GB18030 / UTF-16 / CRLF；Markdown；测试内生成的 DOCX；无标题回退；标题误判；无内容丢失（所有非标题行都出现在某章正文）；取消不落库；1000 章批量插入。
- 验收：100 万字 TXT 导入成功，章数与预览一致，正文无丢失，进度可见，可取消。

**估时：** 5 天。 **依赖：** P0。

### E1 平台格式导出与单章复制

**目标：** 作者能把整本或一章导出成平台后台可直接粘贴的格式，预览与文件一致。

**用户故事：** 我不想每次发布都手动删标题、改缩进、调空行。

**数据与接口：**
- 新增 `data/ExportPresets.kt`：`ExportPreset(id, name, chapterTitleFormat, volumeTitleFormat, indent, blankLine, includeBlurb)`；内置「通用网文 / 起点 / 番茄 / 晋江 / 纯文本 / Markdown」；token `{n}`、`{cn}`、`{title}`、`{book}`。
- `Exporter.Options` 增加 `preset: ExportPreset`；`Exporter.write(bookId, options, OutputStream)` 逐章流式写出；新增 `renderPreview(bookId, options, maxChars=20000)` 供导出页预览，保留现有 `render()` 的全量语义（测试和整本复制仍用它）。
- `Prefs` 增加 `exportPreset: String = ""`（JSON，空=默认）。
- 编辑器 ⋮ →「复制本章」：仅正文 / 正文+标题 / 书名+标题+正文；用系统剪贴板。

**文件：** `data/ExportPresets.kt`（新增）、`data/Backup.kt`（`Exporter`）、`ui/routes/ExportRoute.kt`（从 `DataRoute.kt` 拆出）、`ui/routes/EditorRoute.kt` / `EditorAi.kt`（复制菜单）、`data/Prefs.kt`、i18n。

**边界与失败：** 模板含未知 token（保留原文并提示）；导出中断；空书/空章；剪贴板不可用；平台格式变化（文案提示以平台后台预览为准）。

**测试与验收：** `ExportPresetTest`（token、各预设）、`ExporterStreamTest`（stream 与 render 一致）、`ExporterPreviewTest`（预览截断但前缀一致）、`ChapterCopyTest`（三种格式）。验收：预览和文件一致；单章复制正确；不联网。

**估时：** 2 天（与 E2 合并 5 天）。 **依赖：** P0。

### E2 发布前检查

**目标：** 发布前在本机检查标题、字数、标点、自定义风险词和 AI 标记占比，减少「发出去才发现」的问题。

**用户故事：** 我想在发布前五分钟过一遍，而不是靠记忆。

**数据与接口：**
- 新增 `data/PublishCheck.kt`：
  - `run(bookId, chapterId?): Report`，纯本地、无 AI。
  - 规则：标题空/超长/全书重名；空章/字数低于阈值（默认 1000）；中英文标点混用、连续标点、引号/括号不成对、段首多余空格；自定义风险词；AI 标记占比；文风禁用词/AI 味命中数（只提示）。
  - AI 标记：合并重叠区间，分别输出 `gen` / `edited` 字符占比和段数；分母用正文字符数；不判定合格/不合格。
- 风险词表：`filesDir/compliance/words.txt`，支持每行一个词或 `类别|词`；从 TXT 导入/导出；不内置第三方词库。
- 新增 `data/EditorJump.kt`：进程内 `put(chapterId, offset)` / `consume(chapterId)`，检查结果点「去原文」时用，避免改现有路由。
- 报告可导出 TXT/MD。
- 页面固定说明：「本地检查只覆盖格式、自定义词和 AI 标记，不构成平台合规保证；不用于规避检测。」

**文件：** `data/PublishCheck.kt`（新增）、`data/EditorJump.kt`（新增）、`ui/routes/PublishCheckRoute.kt`（新增）、`ui/routes/DataRoute.kt` / `ui/LingWriteApp.kt`（路由/入口）、`ui/routes/EditorRoute.kt`（消费跳转）、`data/Prefs.kt`、i18n。

**边界与失败：** 全书 500 章性能（逐章扫描、不拼接全文）；检查时章节被删；偏移失效（clamp）；词表空/重复/含分隔符；跳转到其他章前保存当前稿；深色/浅色可读性。

**测试与验收：** `PublishCheckTest`（每条规则正反例、AI 占比重叠/越界、词表导入）、`EditorJumpTest`。验收：注入问题全部报出；报告可导出；断网可用；不出现「过检测/降 AI 率」字样。

**估时：** 3 天（与 E1 合并 5 天）。 **依赖：** P0、E1。

### F1 专注写作模式

**目标：** 一键进入只看到正文的状态；光标停在舒适位置；目标与计时可见但不打扰。

**用户故事：** 地铁上十分钟，我想打开就写，不想先滑过一堆卡片和按钮。

**入口与流程：** 编辑器顶部「专注」图标或 ⋮ 菜单；退出需确认（未达目标只提示，不强制锁）。专注中隐藏顶栏、底栏、便签角标、校对条、节拍清单、AI 建议卡；保留正文、极简进度行、退出按钮和键盘。

**数据与接口：**
- `Prefs` 增加 `focusTarget: Int = 2000`、`focusTypewriter: Boolean = true`、`focusHideMarks: Boolean = false`。
- 专注状态只在本页 `rememberSaveable`，不写数据库。
- `EditorScreen` 增加 `focus: Boolean`、`onExitFocus`、`typewriter: Boolean`；`ManuscriptField` 增加 `typewriter`，用 `TextLayoutResult.getLineTop` + `scrollState.animateScrollTo` 把光标行放到视口 40%。
- 计时用开始时间戳计算，不依赖 tick 累加；可选 25 分钟倒计时。
- 屏幕常亮：`LocalView.current.keepScreenOn = true`，离开/退出恢复。
- 设置页增加「专注模式」：默认目标、打字机、隐藏 AI 标记。

**文件：** `ui/screens/EditorScreen.kt`、`ui/routes/EditorRoute.kt`、`data/Prefs.kt`、`ui/routes/SettingsRoute.kt`、i18n。

**边界与失败：** 键盘弹出/收起改变视口；大字号；分屏/平板；无目标的书；旋转；离开页面时自动保存链路不受影响；计时跨后台。

**测试与验收：** 纯函数 `typewriterScrollTarget(lineTop, lineHeight, viewport, ratio)`；`FocusTimerTest`（时间戳）；Robolectric UI 进出专注不丢正文；浅/深色截图。验收：目标进度正确；打字机不抖动；无强制锁；退出后恢复原布局。

**估时：** 3 天。 **依赖：** P0。

### Q1 编辑器速查

**目标：** 写作时不用离开编辑器就能查当前章相关的设定、伏笔、前情和全书搜索。

**用户故事：** 写到「沈砚」时忘了她此刻的境界和称呼，我不想切页面。

**入口与流程：** 编辑器底栏「速查」或 ⋮ 菜单；半屏/全屏面板，四个标签：设定 / 伏笔 / 前情 / 搜索。只读。

**数据与接口：**
- 新增 `data/QuickRef.kt`（纯函数 + 聚合）：
  - `relevantCards(bookId, chapterNumber, text, plan)`：`inject`、正文/章纲命中、`firstChapter`；用 `resolveAt` 取当章状态。
  - `foreshadowsFor(bookId, chapterNumber)`：open/due/overdue，优先当前章/关联卡。
  - `recentSummaries(bookId, chapterNumber, n=5)` + 当前卷摘要。
  - `search(bookId, query)`：确保索引（用 P0 的 stale 查询增量重建）后调用 `ContextEngine.search`。
- 点结果：同章用 `EditorJump` 定位；跨章先保存当前稿并确认，再跳转。
- 不调用 AI，不写正文。

**文件：** `data/QuickRef.kt`（新增）、`ui/routes/EditorQuickRef.kt`（新增）、`ui/screens/EditorScreen.kt`（入口/面板参数）、`ui/routes/EditorRoute.kt`（保存/跳转）、`data/EditorJump.kt`、i18n。

**边界与失败：** 无设定/无伏笔/无摘要；500 章列表（LazyColumn）；搜索索引重建中；无结果；面板打开时继续输入；跨章保存失败；IME 遮挡。

**测试与验收：** `QuickRefTest`（相关性、当章状态、搜索聚合）；Robolectric UI 打开/切标签；截图。验收：索引已热时打开 ≤ 300ms；结果定位准确；零正文写入。

**估时：** 3 天。 **依赖：** P0。

## 4. 执行规则

- **数据库：** 本版本不改表、不升 schema。任何实现中发现必须改表，停下来改计划，顺延到 v0.5，不在 v0.4 夹带迁移。
- **PR：** 一个任务卡一个 PR；分支 `v0.4/<name>`；提交前 `git diff --check`；CI 绿灯才算完成；不强推、不改写已推送历史。
- **测试：** 解析/聚合/纯函数先写单测；Room 测试用 `LingDatabase.build(ctx, inMemory = true)`；UI 用 Robolectric；新页面至少浅/深色截图。
- **i18n：** 新文案进 `tools/i18n/extracted.json`，跑 `python3 tools/i18n/gen.py`，四语齐全；AI 提示词保持中文。
- **隐私：** 导入/导出/检查/速查全部本地；不新增网络请求和权限；不引入统计 SDK。
- **文档：** 每个 PR 更新 `PROGRESS.md` 对应条目；新增入口写进 README 前先确认已发布。
- **本机限制：** 构建机无 JDK，以 GitHub Actions 为准；exFAT 下写文件用脚本，`._*` 不入库。

## 5. 产品约束（不可协商）

1. 不帮助规避 AI 检测：不做「降 AI 率」「过检测」「伪装人写」；发布检查只做格式/词表/标记统计。
2. AI 生成内容一律先候选，作者确认后才写入正文；辅助模式不自动写正文。
3. 导入/导出/检查不抓取平台、不上传正文。
4. 风险词表由作者维护，App 不内置第三方敏感词库，不宣称平台合规保证。
5. 本地、免登录、无遥测不变。

## 6. 风险

| 风险 | 影响 | 应对 |
|---|---|---|
| 导入标题误判 | 章节错乱 | 预览 + 三种拆分 + 可取消 + 失败回滚 |
| 备份精简丢自动历史 | 少恢复点 | 手动/回滚/AI 版本全保留；完整备份可选；文案写明 |
| 升级快照只备份不恢复 | 灾难需人工 | 可导出；文档写清；后续再评估 |
| 100 万字性能未实测 | 仍可能卡 | 夹具 + 真机门；不达标不发布 |
| 专注模式改动编辑器布局 | 影响日常写作 | 专注是独立状态；退出恢复；截图 + 手测 |
| 发布检查被误当合规保证 | 作者误判 | 固定免责声明；词表作者维护；不显示「通过/不通过」 |
