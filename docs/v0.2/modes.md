# 辅助模式 vs 生成模式：现状核查与重新定义

## 1. 现状核查（v0.1.0 代码）
`prefs.writeMode`（`"assist"` / `"generate"`）在代码里**只有 4 处被读取**：

| 位置 | 作用 |
|---|---|
| `ui/screens/FirstRunScreen.kt` | 首次选择，两种都不预选 |
| `ui/LingWriteApp.kt:79` | 保存首次选择的结果 |
| `ui/routes/SettingsRoute.kt:29–41` | 设置里显示和切换 |
| **`ui/routes/EditorAi.kt:95`** | **唯一影响行为的地方**：编辑器在**没选中文字**时显示哪组工具 |

`data/ai/Prompts.kt:43–45`：
- 辅助模式：`assistTools = [给方向, 润色, 去 AI 腔, 改写]`
- 生成模式：`generateTools = [续写, 改写, 扩写, 润色, 去 AI 腔, 对话]`
- 选中文字时两种模式**完全一样**：`selectionTools`

**一句话结论：两种模式目前只差"未选中文字时工具条上的几个按钮"，其余行为完全相同，而且辅助模式本身还有两处违背自身定义的 bug。** 用户"看不出区别"是准确的。

辅助模式的两处 bug：
1. **"给方向"被采纳后，会直接插进正文并标成 AI 生成段**。`accept()` 对所有工具都调用 `st.replace(..., "gen")`，按钮文案"插入备注"名不副实。这和"AI 建议默认不进正文"相矛盾。
2. 辅助模式工具条上的"润色 / 去 AI 腔 / 改写"都是 `needsSelection = true`。没选中文字时点它们，提示词里的「」是空的，模型只能乱写。

其他页面（大纲拆章纲、向导、一致性检查、随手问）都**不区分模式**。

## 2. 重新定义（v0.2）
两种模式地位平等，首次使用时都不预选，随时可以切换。**区别在于：AI 能否把文字写进正文，以及 AI 默认产出什么。**

| | 辅助模式 · 「你写，AI 陪」 | 生成模式 · 「你定，AI 起草」 |
|---|---|---|
| 一句话 | 正文每个字出自你手；AI 给方向、提问题、指出问题，并帮你改你选中的句子 | 你定章纲，AI 起草段落或整章，你来挑、改、定稿 |
| AI 能否把新文字写进正文 | **不能**。只有"选中文字 → 改写类工具 → 采纳替换"这一种情况例外，因为改的是你自己写的句子；采纳后标为"AI 建议 + 人工修改" | 能。续写、对话、起草整章，采纳后插入正文，标为"AI 生成" |
| 默认产出 | 提纲式要点、问题清单、批注；放在**侧边面板或便签**，不进正文 | 可以直接用的正文候选（2–3 条），左右滑动切换 |
| 未选中文字时的工具条 | 给方向 · 随手问 · 卡文急救 · 校对本章 · 本章自查 | 续写 · 起草本章 · 对话 · 描写 · 随手问 · 校对本章 |
| 选中文字时的工具条 | 润色 · 去 AI 腔 · 改写 · 缩写 · ＋批注（改写类结果是**并排对比**，采纳时按"人工修改"计） | 改写 · 扩写 · 润色 · 去 AI 腔 · 描写 · 缩写 · ＋批注 |
| 章纲 → 正文 | 生成"场景节拍"：5–8 条要点，作为编辑器顶部的可勾选清单 | "起草本章"：按章纲生成整章草稿，放进草稿区，分段采纳 |
| 采纳的去向 | 方向和节拍进入"本章便签"（`ChapterNoteEntity`，新增），不进正文 | 进入正文，带 AI 段落标记 |
| 自动任务（摘要、检查、伏笔、设定整理） | 相同 | 相同 |
| 大纲 / 向导 / 总纲链路 | 相同：AI 都给候选，作者微调后采纳。大纲不是正文，两种模式不区分 | 相同 |
| AI 使用记录 | 相同 | 相同 |

## 3. 让用户明显感知到区别
1. **编辑器顶栏的模式徽章**（新增）：标题右侧显示一个胶囊。
   - 辅助模式：`primaryContainer` 底，图标 `draw`，文字"辅助"。
   - 生成模式：`tertiaryContainer` 底，图标 `auto_awesome`，文字"生成"。
   - 点徽章弹出"切换写作模式" Sheet（见第 4 节）。
2. **AI 主按钮外观**：
   - 辅助模式：描边按钮，图标 `lightbulb`，文字"灵感"；
   - 生成模式：实心主色按钮，图标 `auto_awesome`，文字"AI 起草"。
3. **结果呈现方式不同**：
   - 辅助模式的结果是**便签卡**：浅色底、左侧 3dp 主色竖条、要点列表，按钮为"存到便签 / 复制 / 再来一次"，**没有"采纳到正文"**。
   - 生成模式的结果是**候选卡**：琥珀色竖条、`1/3` 页码和左右滑动，按钮为"换一批 / 微调 / 采纳"。
4. **空状态文案**：编辑器正文为空时的占位文字。
   - 辅助模式："从这里开始写。卡住了可以点「灵感」，AI 会给方向，不会替你写。"
   - 生成模式："先在章纲里写好本章要发生什么，再点「AI 起草」。"
5. **首次进入编辑器时的一次性提示条**，按当前模式显示不同文案，带"知道了"按钮，记在 `prefs.modeTipShown`。
6. **作品可以单独设置模式**（新增 `BookEntity.writeMode`，可空，空表示跟随全局）。在作品信息 Sheet 里设置，显示为"本书写作模式：跟随全局 / 辅助 / 生成"。

## 4. 入口与切换方式
- 首次使用：`FirstRunScreen` 两张卡片都不预选。卡片文案按第 2 节的一句话和"默认产出"一行更新，底部加一句"随时可以在编辑器顶栏或设置里切换"。
- 全局：设置 → 写作 → 写作模式（现有）。
- 编辑器顶栏模式徽章：切换的是**本书**模式。Sheet 里有两个选项和一个"应用到所有作品"勾选。
- 切换时：
  - 已经插入正文的 AI 段落不变；
  - 切到辅助模式时，如果生成模式还有未采纳的候选，弹出确认："当前候选会存进本章便签"。
- 相关提示文案：
  - 辅助模式："AI 不会往正文里写字，给你的都是方向、问题和对你选中句子的改法。"
  - 生成模式："AI 会起草正文候选，采纳前可以先改；采纳后的段落会标出来，导出时不带标记。"

## 5. 各页面的差异表
| 页面 / 功能 | 辅助模式 | 生成模式 |
|---|---|---|
| 编辑器工具条（未选中文字） | 给方向、随手问、卡文急救、校对、本章自查 | 续写、起草本章、对话、描写、随手问、校对 |
| 编辑器工具条（选中文字） | 润色、去 AI 腔、改写、缩写、批注（结果并排对比） | 改写、扩写、润色、去 AI 腔、描写、缩写、批注 |
| 编辑器结果 | 便签卡，进本章便签 | 候选卡（N 条），进正文 |
| 章纲 → 正文 | 场景节拍清单 | 整章草稿 |
| 总纲链路最后一步（第一章） | 生成第一章的节拍清单和开篇三种写法示意（每种 ≤ 80 字，只作参考，不入正文） | 生成第一章草稿候选 |
| 卡文急救 | 只给问题和方向 | 同左，另加"按这个方向起草一段"（结果进候选卡） |
| 一致性问题"给改法" | 只给建议，进便签，作者自己改 | 以批注修改的方式给出改动，逐条接受 |
| 校对 | 两种模式相同：逐条接受。只改错字和标点，不算 AI 生成 | 相同 |
| 大纲、向导、设定库、伏笔、灵感、统计 | 相同 | 相同 |

## 6. 实现要点（任务卡 MD1–MD3，见 v0.2-plan.md）
- 新增 `data/Mode.kt`：`enum class WriteMode { Assist, Generate }`、`suspend fun modeFor(bookId): WriteMode`（作品设置优先，没有则用全局）、`object ModeCopy`（集中放所有文案）。
- `Prompts` 改成 `ToolSet.forMode(mode, hasSelection)`；每个 `Task` 增加 `output: Output { Note, Candidate, Replace }`，`accept()` 按 `output` 分别处理：
  - `Note` → 写入 `ChapterNoteEntity`，**绝不进正文**；
  - `Replace` → 只在有选中范围时可用，标为 `edited`；
  - `Candidate` → 插入正文，标为 `gen`。
- 修复第 1 节的两处 bug：`needsSelection` 的工具在没选中文字时不显示，作为独立回归测试。
- 迁移 2 → 3：`books` 加 `writeMode TEXT`（可空）；新建 `chapter_notes(id, chapterId, kind, text, done, createdAt)`。
- 测试：
  - `ModeTest`：辅助模式下所有 `Note` 工具在 `accept` 后正文长度不变，`chapter_notes` 增加 1 条；生成模式下候选采纳后正文出现 `gen` 标记。
