## 4. 执行规则（每个 agent 必须遵守）
- **提交与推送**
  - 每完成一张卡就提交并推送一次，推送前必须能编译、测试全部通过。
  - 不强推，不改写已推送的历史，不 `reset --hard` 远端分支。
- **编译和测试命令**
  ```
  cd android && export ANDROID_HOME=/opt/android-sdk
  ./gradlew assembleDebug assembleRelease testDebugUnitTest -q
  grep -l "<failure" app/build/test-results/testDebugUnitTest/*.xml   # 应无输出
  ```
  截图测试：`./gradlew recordRoborazziDebug`（记录）或 `verifyRoborazziDebug`（校验）。
- **签名**
  - 签名密钥不入库：维护者本机备份 + GitHub Actions Secrets，打 tag 时由 CI 签名发版。
  - 每个版本都用同一把密钥签名，证书 SHA-256 为 `f31f5b4f…fce52`。
  - 不要提交任何密钥、keystore 或 API Key。
- **发版**
  - 每次发版 `versionCode` + 1。
  - 用 `apksigner verify` 检查，用 `sha256sum` 生成校验值，发布说明里写 `SHA-256: <hex>`。
  - 必须是正式 Release，不能是预发布。
- **数据库**
  - 每次改表都要 version + 1、写显式 `Migration`、提交 schema JSON，并补上 `MigrationTest`。
  - 不允许破坏性迁移。
- **界面**
  - 所有新界面都要有浅色和深色截图，和 `ui-hifi/v0.2` 对照，误差 ≤ 4dp。
  - 动效只引用 `Motion` token，并遵守 `Motion.reduced`。
- **进度**
  - 每个 PR 都要更新 `PROGRESS.md`（完成了哪些、还剩哪些）。

## 5. 产品约束（不可协商）
1. **不做任何帮助规避 AI 检测的功能**：不做"降 AI 率"、"过检测"、"伪装人写"，也不提供"去 AI 腔"之外的改写伪装。现有的"去AI腔"只定位为改善文风，文案和提示词里都不能提到"检测"。
2. **AI 生成的内容一律先给候选**：用户可以微调，确认采纳之后才写入；任何功能都不能静默改动正文、设定或大纲。
3. 辅助模式下，AI 从不往正文写入新内容（唯一例外：用户主动对选区发起的改写，并且采纳前要先看到候选）。
4. AI 写入的内容保留 gen / edited 来源标记；导出时可以选择是否去掉。
5. 拆文只在本地分析用户自己粘贴的文本，不抓取，不保存原文全文（只保存结构化结果）；页面上显示版权提示。
6. 读者反馈页明确标注"模拟反馈，仅供参考"。

## 6. 风险
| 风险 | 影响 | 应对 |
|---|---|---|
| 7 次迁移叠加，覆盖升级失败 | 用户数据丢失 | 每次迁移都写 MigrationTest，R1 测一次 1→7 连续迁移，迁移前自动备份（复用 Backup） |
| 模型输出的 JSON 不稳定 | 候选为空、报错 | F3 重试并给出降级文案，所有解析都有单元测试 |
| 多候选和读者反馈的 token 成本高 | 用户费用 | 发起前显示费用预估，N 默认 2，读者画像默认 1 个，用量条预警 |
| Box 上没有模拟器 | 没法做端到端和性能测试 | 用截图测试和单元测试兜底；每个里程碑结束让用户在真机上冒烟测试；基准只要求能编译 |
| 模式重定义改变了老用户的习惯 | 用户困惑 | 首次使用提示，迁移时现有作品继承全局模式，设置里可以切换 |
| 命名迁移中，正则误删用户自己写的"第X卷"文字 | 卷名受损 | 只剥离开头符合 `^第[0-9一二三四五六七八九十百千]+[卷章]\s*[·:：]?\s*` 的部分，迁移前备份，并写测试用例 |
| 应用内更新在私有仓库下不可用 | 用户收不到更新 | 已知问题，沿用 v0.1 的说明，等用户决定是否公开发布渠道 |
| 并行 PR 抢同一个 Room 版本号 | 合并冲突 | 版本号按里程碑预先分配；后合并的 PR 顺延 |
