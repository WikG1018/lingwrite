# 灵写 v0.5 计划：写作闭环

> 状态：规划稿（2026-10-17），尚未实现。
> 上级文档：[author-roadmap.md](author-roadmap.md)。前置版本：[v0.4-plan.md](v0.4-plan.md)。
> 本版本**数据库 8 → 9**，必须显式迁移、提交 schema、补迁移测试，并在发布前做真机覆盖升级。

## 1. 范围

1. 追读数据复盘：手动/粘贴录入平台数据，按章曲线、可疑掉点、本地诊断，可选 AI 分析。
2. 大纲-正文同步：以正文回写章纲、快照可撤销、滚动规划 CTA、卷完成度。
3. 一致性扩展：地理/物品/称谓/信息差四类 + 章节事件轴。
4. AI 使用体检：AI 标记占比、采纳率、按章/任务/模型报告，可导出。
5. 听稿（系统 TTS）：按段朗读、暂停、语速、生命周期。
6. 发布 v0.5.0（versionCode 17，versionName 0.5.0）。

**不在本版本：** 系列共享设定（v0.6）、场景级协作流（v0.6）、EPUB 导入、WebDAV 同步。

## 2. 数据库 8 → 9

### 2.1 新表

```sql
CREATE TABLE IF NOT EXISTS `read_metrics` (
  `id` INTEGER PRIMARY KEY AUTOINCREMENT NOT NULL,
  `bookId` INTEGER NOT NULL,
  `chapterNumber` INTEGER NOT NULL,
  `platform` TEXT NOT NULL DEFAULT '',
  `recordedAt` INTEGER NOT NULL,
  `reads` INTEGER NOT NULL DEFAULT -1,
  `completion` INTEGER NOT NULL DEFAULT -1,
  `favorites` INTEGER NOT NULL DEFAULT -1,
  `comments` INTEGER NOT NULL DEFAULT -1,
  `note` TEXT NOT NULL DEFAULT '',
  FOREIGN KEY(`bookId`) REFERENCES `books`(`id`) ON UPDATE NO ACTION ON DELETE CASCADE
);
CREATE INDEX IF NOT EXISTS `index_read_metrics_bookId_chapterNumber_recordedAt`
  ON `read_metrics` (`bookId`, `chapterNumber`, `recordedAt`);

CREATE TABLE IF NOT EXISTS `chapter_plan_versions` (
  `id` INTEGER PRIMARY KEY AUTOINCREMENT NOT NULL,
  `chapterId` INTEGER NOT NULL,
  `bookId` INTEGER NOT NULL,
  `planJson` TEXT NOT NULL,
  `note` TEXT NOT NULL DEFAULT '',
  `createdAt` INTEGER NOT NULL,
  FOREIGN KEY(`chapterId`) REFERENCES `chapters`(`id`) ON UPDATE NO ACTION ON DELETE CASCADE,
  FOREIGN KEY(`bookId`) REFERENCES `books`(`id`) ON UPDATE NO ACTION ON DELETE CASCADE
);
CREATE INDEX IF NOT EXISTS `index_chapter_plan_versions_chapterId`
  ON `chapter_plan_versions` (`chapterId`);
CREATE INDEX IF NOT EXISTS `index_chapter_plan_versions_bookId`
  ON `chapter_plan_versions` (`bookId`);
```

### 2.2 修改表

```sql
ALTER TABLE `chapter_plans` ADD COLUMN `storyTime` TEXT NOT NULL DEFAULT '';
```

`storyTime` 是作者填的「故事内时间」标记（如「第三天清晨」「三年后」），不是系统时间；事件轴和一致性检查会显示/使用它，允许为空。

### 2.3 迁移与备份

- `LingDatabase.version = 9`；新增 `MIGRATION_8_9`；提交 `schemas/.../9.json`。
- `Backup.tables` 追加 `chapter_plan_versions`（在 `chapter_plans` 之后）与 `read_metrics`（在 `books` 之后均可，按依赖顺序）；旧备份缺表时现有 restore 逻辑跳过。
- `Backup.legacyDefaults` 不需要给新表补默认值；`read_metrics` 的 `-1` 表示「平台没给这个数」，不是 0。
- 章号重排：`BookRepository.remapChapterNumbers()` 增加 `read_metrics.chapterNumber` 的重映射（与伏笔、读者反馈同口径）；必须补「插章/删章后追读数据跟着章走」的测试。
- 迁移测试：`migrate8To9()` 手工建 v8 库 + 写入书籍/章节/章纲/伏笔 → 迁移 → 断言新表、列、索引、数据；`roomOpensAfterFullChainMigration()` 全链打开。

## 3. 任务卡

### R1 追读数据复盘

**目标：** 作者把平台后台的追读/完读/收藏数据录进来，看到按章曲线和可疑掉点，知道该回头改哪几章；数据只在本机。

**用户故事：** 追读掉了，我不知道是第几章开始掉的，也不知道和章末钩子有没有关系。

**入口与流程：** 作品页 ⋮ 或统计 tab →「追读数据」；支持逐章手动录入、粘贴 CSV/TSV（表头别名）、覆盖/删除单章；解析失败逐行提示；空态说明「平台数据需手动获取，灵写不抓取后台」。

**数据与接口：**
- 新 `data/ReadStats.kt`：`ReadMetric`、`parseTable(text)`、`latestPerChapter(rows)`、`insights(rows, plans)`。
- `ReadStatsDao`：`rows(bookId)` Flow、`insert/update/delete`、`latest(bookId)`、`range`。
- 表头别名：章/章节/章节名/Chapter；追读/阅读/UV/reads；完读/读完率/完读率/completion；收藏/加书架/favorites；评论/comments；平台/platform；日期/time。
- 数值兼容 `12.3%`、`0.123`、`12.3`；统一存百分数整数（0–100，四舍五入）；缺失存 -1。
- 图表：Compose Canvas 折线（追读、完读率），无新依赖；最近 30 章/全书切换。
- 本地诊断：相对前章下降 ≥10%、低于全书中位数、章纲无 `cliff`、字数低于本书均值；只显示「可能相关」，不写因果。
- 可选 AI 分析：`data/ReadStatsPrompts.kt`，只发送数字 + 章摘要 + 章纲字段（不发正文）；输出 JSON 结论；作者确认后存为便签；不自动改数据。

**文件：** `data/db/ReadStatsEntities.kt`（新增，实体 + DAO）、`Daos.kt`（如需要共享查询）、`LingDatabase.kt`、`data/ReadStats.kt`（新增）、`data/ReadStatsPrompts.kt`（新增）、`ui/routes/ReadStatsRoute.kt`（新增）、`ui/routes/WorkRoute.kt`/`StatsRoute.kt`（入口）、`data/BookRepository.kt`（重映射）、`data/Backup.kt`、i18n。

**边界与失败：** 平台列名/顺序变化；重复行（取同一章最新 recordedAt，时间相同取 id 大者）；章号超出当前书；负数/空值；粘贴 5000 行上限；章节被删后数据标灰、不物理删；AI 分析失败不破坏本地数据；多平台数据混在同一本书时按 `platform` 区分或提示。

**测试与验收：** `ReadStatsParseTest`（表头、百分号、CSV/TSV、坏行）、`ReadStatsInsightTest`（掉点/中位数）、`RenumberReadMetricsTest`、`MigrationTest 8→9`、备份 round-trip。验收：粘贴 100 章数据与源一致；图表与手工计算一致；重排章号后不错位。

**估时：** 5 天。 **依赖：** v0.4 完成；无其他任务依赖。

### O1 大纲-正文同步

**目标：** 正文偏离章纲时，作者能一键把「实际写出来的内容」回写成章纲，旧章纲保留可撤销；低章纲余量时能直接规划后 3–5 章。

**用户故事：** 我写出来的和原章纲不一样，但新的其实更好；我想让大纲追上正文，而不是每次手改。

**入口与流程：**
- 章纲编辑页 / 编辑器「本章章纲」：`landed` 有 `false` 项时显示「以正文更新章纲」。
- AI 根据正文 + 旧章纲 + 未落实项生成完整章纲草稿（event/hook/cliff/note/storyTime），显示逐字段 diff；作者可逐项/整体接受。
- 接受前写 `chapter_plan_versions`（旧 plan JSON），可撤销。
- 不接受时零写入。
- 连载看板 `planAhead < 3` 显示「规划后 3–5 章」，复用现有拆章纲流程。
- 卷完成度：`chapterCount` 与实际章数对比，>120% 提示「卷纲可能失效」。

**数据与接口：**
- `PlanDao` 增加 `planVersions(chapterId)`, `insertPlanVersion`, `prunePlanVersions(chapterId, keep=10)`。
- 新 `data/PlanSync.kt`：`snapshot(plan, note)`、`restore(versionId)`、`diff(old, new)`、`volumeProgress(bookId)`、`landedGaps(plan, landed)`。
- `Outline.kt` 增加 `OutlinePrompts.resync(plan, text, landed)`：只输出 JSON，字段与 `ChapterPlanEntity` 对齐，`storyTime` 可选；不接受时不动库。
- 冲突保护：生成时记录正文 hash/字数；接受时若正文又变，要求重新生成。

**文件：** `data/db/PlanEntities.kt`、`Daos.kt`、`LingDatabase.kt`、`data/Outline.kt`、`data/PlanSync.kt`（新增）、`ui/routes/OutlineRoute.kt`、`ui/routes/SerialBoardCard.kt`、`ui/routes/EditorRoute.kt`、i18n。

**边界与失败：** 正文/章纲为空；AI 返回缺字段（走 `JsonReply` 重试，仍失败则报错）；接受前正文被改；撤销时章节被删；`storyTime` 手工留空；不自动生成章纲。

**测试与验收：** `PlanSyncTest`（快照/撤销/完成度/冲突）、`OutlineResyncPromptTest`（JSON 契约）、迁移与备份、UI 截图。验收：接受后章纲更新且可恢复；不接受时数据库无变化；CTA 只在低余量出现。

**估时：** 4 天。 **依赖：** 数据库 8→9 完成。

### C1 一致性扩展 + 章节事件轴

**目标：** 在现有四类之外，检查地点距离、物品归属、称谓变化、信息差；同时提供按章节的事件流，减少翻前文。

**用户故事：** 读者说「这里人物不该知道这件事」「这把剑上一章不是断了吗」；我想让工具先替我盯住。

**一致性扩展：**
- `Consistency.comparePrompt` 的 `kind` 增加：`geography`（地点/距离/方位/气候）、`item`（物品归属/能力/损毁）、`title`（称谓/身份称呼）、`knowledge`（信息差：角色此时不该知道/早该知道）。
- `kindLabel()` 同步；旧 kind 原样显示。
- 复用两步检查与「故意为之」抑制；不增加 AI 调用次数；继续要求逐字引文；不确定/人物说谎/视角受限不报。
- 设置/检查页增加类型开关（`prefs.checkKinds`，空=全开），控制新类型是否参与。

**章节事件轴：**
- 新 `data/Timeline.kt`：从 `lore_states`（字段变化）、`lore_relations`（关系变化）、`foreshadows`（埋设/计划回收）、`chapter_plans`（event/storyTime）、章节完成状态派生事件；按章排序，显示 `storyTime`。
- 新 `TimelineRoute`：纵向事件流、章/卷分组、筛选（人物/实力/关系/地点/物品/伏笔/全部）；点击跳设定卡或章节。
- 文案明确「按章节顺序；故事内时间以章纲标注为准」，不宣称完整故事时间线。
- 窄查询 + LazyColumn；不加载正文。

**文件：** `data/Consistency.kt`、`data/Timeline.kt`（新增）、`ui/routes/CheckRoute.kt`、`ui/routes/TimelineRoute.kt`（新增）、`ui/LingWriteApp.kt`、`data/Prefs.kt`、i18n。

**边界与失败：** 旧问题 kind 未知；无 `storyTime`；同章事件过多；关系/状态指向已删除卡；筛选空态；新类型误报（类型开关 + 故意为之）。

**测试与验收：** `ConsistencyPromptTest`（四类新 kind）、`TimelineTest`（排序/筛选/缺失字段）、旧 issue 兼容、截图。验收：能报出注入矛盾；旧数据正常；事件轴不加载正文。

**估时：** 4 天。 **依赖：** 数据库 8→9（`storyTime`）。

### A1 AI 使用体检

**目标：** 作者能看清一本书里 AI 生成/修改段落的占比、采纳率和按章分布，用于自查与说明；明确不是检测规避工具。

**用户故事：** 我只用 AI 改病句和润色，但出了争议时说不清；我想有一份本地报告。

**数据与接口：**
- 新 `data/AiUsage.kt`：
  - `share(text, marks)`：合并重叠区间，按字符计算；输出 `gen` / `edited` 占比、段数、涉及章节。
  - 采纳率：`call_logs.outcome`（accepted/edited/rejected/pending）与 `chosen`；按任务/模型/日期聚合。
  - 修正 `ChapterEntity.toUi()` 的 `aiShare` 使用同一口径（现按 `wordCount` 分母，英文会偏）。
- 复用 `Stats.taskName`，补齐 `title`/`draft`/`read` 等任务名。
- 报告导出 MD/TXT；只读本地，不联网。

**展示：** 新 `AiUsageRoute`：总览卡（gen/edited 字符占比、采纳率）、按章表格（可排序、高占比标色）、按任务/模型分布、导出。固定免责声明：「仅统计 App 内标记的 AI 段落；手工修改/外部粘贴不计入；不能作为平台判定依据，也不用于规避检测。」

**文件：** `data/AiUsage.kt`（新增）、`data/Mappers.kt`、`data/Stats.kt`、`ui/routes/AiUsageRoute.kt`（新增）、`ui/routes/WorkRoute.kt`、`ui/LingWriteApp.kt`、i18n。

**边界与失败：** 标记越界/重叠；空章；英文/日文分母；`call_logs` 被清理；无 AI 调用；大书导出内存（分段/流式）。

**测试与验收：** `AiUsageTest`（重叠、越界、中英日、空）、采纳率聚合、导出内容、截图。验收：占比与手工标注一致；无网络请求；免责声明固定显示。

**估时：** 3 天。 **依赖：** 数据库 8→9（备份/迁移基线），无其他任务依赖。

### T1 听稿（系统 TTS）

**目标：** 作者用「听」抓语病、节奏和重复词，不必一直盯屏幕。

**用户故事：** 改稿改到眼睛疼，我想听一遍。

**实现：**
- 新 `data/Tts.kt`：封装 `TextToSpeech`；初始化/语言可用性检查；按段落/句子切分（复用 `Style.sentences`）；播放/暂停/继续/停止；语速 0.8/1.0/1.2；当前段落回调。
- 编辑器 ⋮ →「朗读本章」sheet；允许从当前段/从头开始；离开编辑器/切后台/来电停止；请求音频焦点；无引擎/无中文语音时提示，不崩溃。
- 隐私说明：系统语音引擎可能联网，由系统设置决定；App 不保存音频；不把正文发给灵写服务器（没有服务器）。

**文件：** `data/Tts.kt`（新增）、`data/Style.kt`（复用切句）、`ui/routes/EditorRoute.kt`（sheet/生命周期）、`ui/screens/EditorScreen.kt`（可选当前段高亮）、`data/Prefs.kt`（`ttsSpeed`）、i18n。

**边界与失败：** 无 TTS 引擎/无中文语音；长章分段（避免单次超长）；来电/其他音频打断；切后台；初始化异步竞态；多音字/方言不保证。

**测试与验收：** `TtsSplitTest`（分段/句子）；初始化失败路径单测（mock）；Robolectric 打开/关闭 sheet 不崩；真机听 10 分钟不崩、不串章。

**估时：** 3 天。 **依赖：** 数据库 8→9（与其他任务同一版本）。

## 4. 执行规则

- **数据库：** 先合迁移 PR（含 schema 9、`MIGRATION_8_9`、迁移测试、备份表），再合功能 PR；功能 PR 不得再改 schema/版本号。
- **PR：** `v0.5/schema9`、`v0.5/read-stats`、`v0.5/outline-sync`、`v0.5/consistency-timeline`、`v0.5/ai-usage`、`v0.5/tts`、`release/v0.5.0`。
- **测试：** 迁移、备份、解析/聚合、章号重排、提示词契约；UI 截图；真机覆盖升级。
- **i18n：** 四语同步；AI 提示词中文；任务名映射补齐。
- **隐私：** 追读数据仅本地；AI 分析显式触发且不发正文；TTS 用系统引擎并说明可能联网。

## 5. 产品约束

1. 不帮助规避 AI 检测；AI 使用体检只做自查，不做「合格/不合格」判定。
2. 追读数据不抓取平台、不上传；只接受作者手动/粘贴输入。
3. 大纲回写必须作者确认；不接受时零写入。
4. 一致性扩展不增加自动改正文的路径。
5. 本地、免登录、无遥测不变。

## 6. 风险

| 风险 | 影响 | 应对 |
|---|---|---|
| 迁移 8→9 出错 | 老用户无法启动 | 显式迁移 + 全链测试 + 升级前快照 + 真机升级 |
| 章号重排追读数据错位 | 分析图错 | 重映射 + 专项测试 |
| 追读格式变化 | 解析失败 | 表头别名 + 手动录入 + 逐行错误 |
| 大纲回写覆盖作者原纲 | 丢内容 | 快照 + 撤销 + diff + 冲突保护 |
| 一致性新类型误报 | 噪音 | 类型开关 + 故意为之 + 逐字引文 |
| TTS 引擎差异 | 无声音/崩溃 | 可用性检查 + 降级提示 + 生命周期测试 |
